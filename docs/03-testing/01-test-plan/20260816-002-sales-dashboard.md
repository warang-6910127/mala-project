# Test Plan: Dashboard ดูยอดขาย

> สร้างเมื่อ: 2026-08-16 | สถานะ: Draft

## วัตถุประสงค์ (Objective)

- ทดสอบ flow ของฟีเจอร์ Should have "Dashboard ดูยอดขาย" ให้ครอบคลุมเกณฑ์การยอมรับทั้ง 4 ข้อใน [[../../01-requirements/01-spec/20260802-002-sales-dashboard|สเปคเต็ม]] และ journey ของเจ้าของร้าน/ผู้จัดการใน [[../../02-design/01-prototypes/user-journey|user-journey]] (หัวข้อ "เจ้าของร้าน/ผู้จัดการดู Sales Dashboard")
- ตัวเลขยอดขายที่ dashboard นี้แสดง มาจาก log ของออเดอร์/การชำระเงินที่ต้องปฏิบัติตาม retention/PDPA ตาม [[../../01-requirements/01-spec/20260802-003-log-retention-pdpa-compliance|สเปค Log Retention/PDPA]] แต่การทดสอบ retention/anonymize อยู่ใน [[20260816-003-log-retention-pdpa-compliance|test plan แยกต่างหาก]] ไม่ทดสอบซ้ำในเอกสารนี้

## ขอบเขตการทดสอบ (Scope)

### สิ่งที่ทดสอบ (In scope)

- การจำกัดสิทธิ์การเข้าถึง dashboard เฉพาะบัญชีเจ้าของร้าน/ผู้จัดการ
- การเลือกดูยอดขายรวมตามช่วงเวลา 3 แบบ: รายวัน, รายสัปดาห์, รายเดือน
- การดูยอดขายแยกตามเมนูในช่วงเวลาที่เลือก
- ความถูกต้องของตัวเลขยอดขายที่แสดง เทียบกับออเดอร์ที่ชำระเงินสำเร็จจริง (reconciliation)

### สิ่งที่ไม่ทดสอบ (Out of scope)

- Custom date range แบบอิสระ, การเปิดให้พนักงานทั่วไปเข้าถึงข้อมูลยอดขาย, การพยากรณ์ยอดขาย/เปรียบเทียบข้ามสาขา — ระบุไว้ชัดเจนแล้วว่าเป็น Out of scope ใน [[../../01-requirements/01-spec/20260802-002-sales-dashboard|สเปค]] จึงไม่ทดสอบ
- การลบ/anonymize log หลัง 90 วัน และช่องทาง manual สำหรับสิทธิ์เจ้าของข้อมูล — มี test plan แยกใน [[20260816-003-log-retention-pdpa-compliance|test plan: Log Retention/PDPA]]
- การสั่งอาหารด้วย QR Code และการแสดง privacy notice — มี test plan แยกใน [[20260815-001-dine-in-qr-table-ordering|test plan: QR Table Ordering]]
- พฤติกรรม UI ที่ยังไม่มีสเปคระบุ (เช่น การจัดวางหน้าจอ, การแสดงผลเมื่อไม่มีข้อมูลยอดขายในช่วงเวลาที่เลือก) — ระบุในหมายเหตุช่องว่างแทนการเดา

## Test Data / เงื่อนไขก่อนทดสอบ

- บัญชีทดสอบอย่างน้อย 2 ประเภท: (1) บัญชีเจ้าของร้าน/ผู้จัดการ (2) บัญชีพนักงานทั่วไปที่ไม่มีสิทธิ์เข้าถึง dashboard
- ออเดอร์ทดสอบที่ชำระเงินสำเร็จแล้ว กระจายอยู่ในช่วงเวลาที่ครอบคลุมทั้งวันนี้ สัปดาห์นี้ และเดือนนี้ อย่างน้อย 2 เมนูขึ้นไปต่อช่วงเวลา เพื่อให้เห็นความแตกต่างระหว่างเมนูในมุมมองแยกตามเมนู
- ออเดอร์ทดสอบที่ **ชำระเงินไม่สำเร็จ** อย่างน้อย 1 รายการ ในช่วงเวลาเดียวกับออเดอร์ที่จ่ายสำเร็จ เพื่อใช้ตรวจสอบว่าตัวเลขยอดขายไม่รวมออเดอร์ที่ยังไม่จ่ายเงิน
- ยอดขายรวม/ยอดขายแยกเมนูที่คำนวณไว้ล่วงหน้าด้วยมือ (expected reference number) จากชุดออเดอร์ทดสอบข้างต้น เพื่อใช้เทียบกับตัวเลขที่ dashboard แสดง
- **ช่องว่างที่พบ**: ยังไม่มี wireframe/prototype ของหน้าจอ Sales Dashboard ภายใต้ `docs/02-design/01-prototypes/prototypes/v1/` ในเวอร์ชันนี้ ทำให้ไม่มีเอกสาร UI ให้อ้างอิงประกอบขั้นตอนทดสอบ (ต่างจาก test plan ของ QR Table Ordering ที่มี prototype ให้อ้างอิง) — ไม่ blocked การทดสอบเชิงพฤติกรรม/ตัวเลข แต่ควรพิจารณาทำ prototype เพิ่มเมื่อออกแบบหน้าจอจริง

## หมายเหตุช่องว่าง (Known Gap)

- ยังไม่มี wireframe/prototype ของหน้าจอ Sales Dashboard ภายใต้ `docs/02-design/01-prototypes/prototypes/v1/` ในตอนที่เขียน test plan นี้ จึงไม่มีเอกสาร UI ให้อ้างอิงประกอบขั้นตอนทดสอบ (ต่างจาก TC ใน [[20260815-001-dine-in-qr-table-ordering|test plan: QR Table Ordering]] ที่อ้างอิง wireframe ได้) — ไม่ได้ blocked การทดสอบเชิงพฤติกรรม/ตัวเลขในเอกสารนี้ เนื่องจากสเปค 002 ระบุพฤติกรรมที่ทดสอบได้ชัดเจนอยู่แล้วโดยไม่ต้องพึ่ง UI ที่เจาะจง แต่ควรจัดทำ prototype เพิ่มเติมเมื่อมีการออกแบบหน้าจอจริง
- สเปค 002 ไม่ได้ระบุพฤติกรรมเมื่อไม่มีข้อมูลยอดขายเลยในช่วงเวลาที่เลือก (empty state) — ไม่ได้เขียนเป็น test case แยกในเอกสารนี้เนื่องจากไม่ใช่เกณฑ์การยอมรับที่ระบุไว้ หากต้องการทดสอบ empty state ควรชี้แจงพฤติกรรมที่คาดหวังกับเจ้าของร้านก่อน
