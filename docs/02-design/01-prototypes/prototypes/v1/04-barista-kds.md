## บริบท

- มาจากขั้นตอน **P→K → K→B** ใน [[../../user-journey|user-journey]] (หัวข้อ "บาริสต้ารับออเดอร์ผ่าน KDS"): ออเดอร์ที่จ่ายเงินสำเร็จถูกส่งเข้าจอ KDS แบบเรียลไทม์ → บาริสต้าเห็นออเดอร์ทันทีเพื่อทำเครื่องดื่มถูกโต๊ะ
- เกณฑ์การยอมรับ/กฎที่ต้อง satisfy: [[../../../../01-requirements/01-spec/20260802-001-dine-in-qr-table-ordering|QR Table Ordering]] ข้อ 4 และกฎทางธุรกิจ "การแจ้งครัว" — "ออเดอร์ที่จ่ายเงินสำเร็จต้องปรากฏบนจอ KDS แบบเรียลไทม์ พร้อมหมายเลขโต๊ะและรายการที่สั่ง" และกฎ "การชำระเงิน" — ออเดอร์ที่ยังไม่จ่ายเงินต้องไม่ปรากฏบนจอนี้เลย
- เรียงลำดับตามเวลาเข้าคิว (เก่าสุดก่อน) ตาม [[../../user-journey|user-journey]]

│  จอ KDS (ครัว)                                                │
├───────────────────────────────────────────────────────────┤
│  [KDS Order Ticket]          [KDS Order Ticket]              │
│  ┌─────────────────────┐    ┌─────────────────────┐          │
│  │ [Table Badge: โต๊ะ 3] │    │ [Table Badge: โต๊ะ 5] │          │
│  │  เอสเปรสโซ x1         │    │  ลาเต้ x2             │          │
│  │  ลาเต้ x1              │    │  อเมริกาโน่ x1         │          │
│  │ [Order Status Tag:    │    │ [Order Status Tag:    │          │
│  │  เข้าคิว 09:03]        │    │  เข้าคิว 09:07]        │          │

## Components ที่ใช้ (อ้างอิง DESIGN.md)

| Component | Token/สี | หมายเหตุ |
|---|---|---|
| KDS Order Ticket | คอนทราสต์สูง `color-text-primary` บน `color-bg-surface` | แสดงเฉพาะออเดอร์ที่จ่ายเงินสำเร็จแล้วเท่านั้น เรียงตามเวลาเข้าคิว (เก่าสุดก่อน) ตรงตามคำอธิบาย component ใน DESIGN.md |
| Table Badge | `color-text-primary`, `text-h2` | อยู่ในแต่ละ ticket เด่นสุดในตั๋ว ตาม UX rule "ความชัดเจนของหมายเลขโต๊ะ" — บาริสต้าต้องรู้ทันทีว่าเป็นของโต๊ะไหน |
| Order Status Tag | สีสถานะ `warning`/`success` ตามช่วงเวลารอ, พื้น `color-surface-alt` | แสดงเวลาที่เข้าคิว (ไม่ใช่ solid fill เต็มพื้นที่) |
| Empty/Loading state | `color-text-muted`, ไอคอนเรียบสีเดียว | ใช้เมื่อยังไม่มีออเดอร์ที่จ่ายเงินสำเร็จรอคิว หรือระหว่างเชื่อมต่อเรียลไทม์ |

## State / Edge cases

- **ออเดอร์ที่ยังไม่จ่ายเงิน**: ต้องไม่ปรากฏบนจอนี้เลย ไม่ว่าในสถานะใด — ตรงตามกฎ "การชำระเงิน" ของ [[../../../../01-requirements/01-spec/20260802-001-dine-in-qr-table-ordering|QR Table Ordering]] (ดูคู่กับ [[03-customer-payment-result|03-customer-payment-result]])
- **ไม่มีออเดอร์รอคิว**: ใช้ Empty/Loading state ตาม DESIGN.md
- **ช่องว่างที่พบ** (อ้างอิงจาก [[../../user-journey|user-journey]] โดยตรง): ขั้นตอน "B→C" (บาริสต้าทำเครื่องดื่มและเสิร์ฟที่โต๊ะ) ระบุไว้ว่า "ยังไม่มีเกณฑ์การยอมรับแยกสำหรับขั้นตอนเสิร์ฟ" — สเปคไม่ได้ระบุว่าบาริสต้าต้องกด "ทำเสร็จ/เสิร์ฟแล้ว" เพื่อลบตั๋วออกจากจอ KDS หรือไม่ ไวร์เฟรมนี้จึงยังไม่แสดงปุ่ม action ใดๆ บนตั๋ว รอการยืนยันเพิ่มเติมจากเจ้าของร้านก่อนออกแบบ interaction นี้
