## บริบท

- มาจากขั้นตอน **B → C → D** ใน [[../../user-journey|user-journey]] (หัวข้อ "ลูกค้าสั่งกาแฟที่โต๊ะด้วย QR Code"): สแกน QR ประจำโต๊ะ → เห็น Privacy Notice สั้นๆ → เลือกเมนู
- เกณฑ์การยอมรับที่ต้อง satisfy:
  - [[../../../../01-requirements/01-spec/20260802-001-dine-in-qr-table-ordering|QR Table Ordering]] ข้อ 1 — "ลูกค้าสแกน QR code ที่โต๊ะแล้วเข้าสู่หน้าสั่งอาหารที่ระบุหมายเลขโต๊ะถูกต้อง" และกฎ "วิธีสั่ง"
  - [[../../../../01-requirements/01-spec/20260802-003-log-retention-pdpa-compliance|Log Retention/PDPA]] ข้อ 1 — ต้องแสดงประกาศความเป็นส่วนตัวก่อนสั่ง/จ่ายเงิน ระบุข้อมูลที่เก็บ (ออเดอร์/การชำระเงิน/หมายเลขโต๊ะ) และวัตถุประสงค์ (ประมวลผลออเดอร์ + วิเคราะห์ยอดขาย) ตามกฎ "Privacy notice" และใช้ฐานทางกฎหมาย "จำเป็นเพื่อปฏิบัติตามสัญญา" (ไม่ต้องมี checkbox/opt-in แยก ตามกฎ "ฐานทางกฎหมาย")

## Components ที่ใช้ (อ้างอิง DESIGN.md)

| Component | Token/สี | หมายเหตุ |
|---|---|---|
| Table Badge | `color-text-primary`, `text-h2` | เด่นสุดในหน้าจอ ตาม UX rule "ความชัดเจนของหมายเลขโต๊ะ" — ต้องขึ้นต่อเนื่องทุกหน้าจอของลูกค้า |
| Privacy Notice Banner | `color-surface-alt` พื้น, ไอคอนเดียว | inline banner ไม่ใช่ modal ไม่มีปุ่ม opt-in/checkbox ตาม UX rule "Privacy notice ต้องไม่ขวางทาง" อ่านจบได้ใน 1-2 วินาที |
| Menu Item Card | `color-bg-surface` พื้น, border บาง, `text-h3` สำหรับชื่อเมนู | รูป + ชื่อเมนู + ราคา + ปุ่มเพิ่ม 1 ปุ่มต่อการ์ด (ปุ่ม `+` เป็นส่วนหนึ่งของการ์ด ไม่ใช่ primary action ของทั้งหน้าจอ) |
| Primary Button | `color-accent-primary`, radius 8px | ใช้ครั้งเดียวในหน้านี้สำหรับ "ดูตะกร้า" (นำไปสู่หน้ายืนยันออเดอร์) ตาม UX rule "1 primary action ต่อหน้าจอ" — คนละปุ่มกับ "ยืนยันออเดอร์ + ชำระเงิน" ที่อยู่หน้าถัดไป |
| Empty/Loading state | `color-text-muted`, ไอคอนเรียบสีเดียว | ใช้ระหว่างโหลดเมนู ไม่ใช้ illustration สีสันจัด |

## State / Edge cases

- **ตะกร้าว่าง**: ปุ่ม "ดูตะกร้า" แสดงจำนวน 0 รายการ — สเปคไม่ได้ระบุพฤติกรรม disable/enable ของปุ่มนี้อย่างชัดเจน จึงไม่ฟันธงพฤติกรรม เพียงแสดงจำนวนรายการให้ลูกค้าเห็นตามจริง
- **เมนูกำลังโหลด/ไม่มีเมนู**: ใช้ Empty/Loading state pattern ตาม DESIGN.md
- **ช่องว่างที่พบ**: สเปค [[../../../../01-requirements/01-spec/20260802-001-dine-in-qr-table-ordering|QR Table Ordering]] และ [[../../user-journey|user-journey]] ไม่ได้ระบุพฤติกรรม UI เมื่อ QR code เสียหาย/สแกนไม่ได้/ชี้ไปยังโต๊ะที่ไม่มีอยู่จริง — ต้องชี้แจงเพิ่มเติมกับเจ้าของร้านก่อนออกแบบ error state จริง ไม่ได้คาดเดาไว้ในไวร์เฟรมนี้
